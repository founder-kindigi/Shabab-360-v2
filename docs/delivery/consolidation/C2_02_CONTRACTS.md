# Canonical contracts for main/v2 consolidation

2026-09-12. **Lead contract decision for future implementation; not implemented or runtime-verified.** `main:` means the pinned published-main copy; `v2:` means the isolated C2-01 candidate, not the untouched original checkout. Identities and actual source call/line evidence are in C2_02_INVENTORY.json. The endpoint register links every competing method/path to the clauses below; the clauses and register must be read together.

## Common contract rules — C00

Current identity, effective capability and resource scope are separate mandatory predicates. Preserve v2 token-version revalidation, forced-reset denial, active assignments and canonical group hierarchy. A group/park assignment cannot become city-wide authority. HQ must deliberately select a city for city-specific operations; aggregate HQ dashboards may be unfiltered only when their own contract permits it. Resolve records and filters before selecting private fields. A membership/share is an additional condition, not an alternative scope grant.

Preserve existing role guards unless a clause explicitly proposes a narrower guard. The capability map does not grant permissions. An effective deny on a canonical capability must not be bypassed through an alias or the other branch's broader `organisation.*` capability. Rich mutation responses additionally require the corresponding read authority; otherwise return only the authorized operation acknowledgement. Do not implicitly turn a manage flag into access to unrelated private fields.

New/reconciled JSON inputs are strict objects. IDs are trimmed, nonempty, max 128; retain existing narrower domain validation, and explicitly reconcile legacy IDs before changing their format requirements. Mutation IDs max 100. General title/name max 200, operational reason max 500; retain a narrower endpoint limit. Reject invalid JSON, impossible dates, duplicate query keys and oversized lists before persistence. Dates representing programme days are `YYYY-MM-DD` in Asia/Karachi; timestamps are ISO instants. A numeric programme `day` is not a weekday.

Reconciled lists use `{data: T[], pagination:{page,pageSize,total,totalPages}}`, default 20/max 100, stable domain sort plus ID tie-breaker, and scope-identical count queries. Existing smaller picker/report limits take precedence. Inherited endpoints explicitly marked “retain v2 shape” keep their current response envelope. Do not force a repository-wide response rewrite. A changed envelope and all listed consumers must ship together; no silent fallback between arrays and objects. No samples after empty/error/denied responses.

Errors: 400 malformed input/required HQ selection; 401 no current identity; 403 forbidden capability, missing actor scope, revoked membership/share or forced reset; 404 absent or undiscoverable target; 409 stale version/reset, duplicate non-idempotent creation, closed state or conflicting parent; 413 bounded upload exceeded; 503 deliberately unavailable workflow. Retain existing documented 422 immutable-access-rule semantics. Never expose raw ORM/errors or another city's record existence.

Retryable side effects use owner-bound OperationReceipt identities, fingerprinted input and transactional domain write + required redacted audit/outbox. A matching retry returns the stored result, not another mutation; a reused ID with changed input is 409. Existing money/stock/attendance protocols remain authoritative. Scalar versions are endpoint-specific: do not coerce attendance's ISO expectedVersion into the integer version used by Media/planner records. A proposed version/receipt field requires the additive data task before API enablement.

No global enablement of an unapproved lifecycle. Gate only the dependent action with an honest 503 `WORKFLOW_NOT_ENABLED`; preserve allowed reads and independent work. External email/push/chat delivery is not established by an outbox insert or an in-app notification row.

## C01 — Media Briefs

Canonical `/api/admin/media/briefs`, `/briefs/[id]`, `/assignees`, `/ui-context`; retain main paths. GET requires `media.workspace.view`; create requires `media.briefs.manage`. Preserve the operation matrix at main `src/app/api/admin/media/briefs/[id]/route.ts:50–80`: editorial fields need briefs.manage or workspace.manage; assignment/asset metadata and general transitions need workspace.manage; draft→open/cancelled also permits briefs.manage; own in_progress→ready_for_review and revision_requested→in_progress permit workspace.view plus active same-city Media membership and assignment ownership. This grants no assignee self-start from open. Check every field in a mixed mutation; response projection also follows C00 read authority. Require baseline authority before processing even a version-only PATCH; reject no changed field. Resolve one stable Media team ID/code, not an arbitrary team with a matching display name. Keep HQ's main Media city-selection supervision behavior; this does not establish a general Teams oversight exemption.

Create fields: cityId (HQ required; scoped staff derived), teamId, title 1–200, description ≤5000, mediaType/priority enums, format ≤100, dueAt; optional contentBlockId must be persisted only after same-team/city validation. PATCH retains main `media-schemas.ts` fields/limits, integer version ≥1 and an explicit field change. Retain its exact lifecycle graph: draft→open/cancelled; open→in_progress/cancelled; in_progress→ready_for_review; ready_for_review→approved/revision_requested; revision_requested→in_progress; approved→delivered/archived; delivered→archived. No transitions out of cancelled/archived. “Delivered” records an approved internal lifecycle state, not provider delivery.

Return minimal brief fields, version, team/assignee references and permitted asset metadata; list omits full descriptions/asset URLs. URLs must pass existing external-link policy; never fetch arbitrary submitted URLs on the server. Assignee picker `q` ≤80, limit 20, scope/activity/membership in the query; output IDs/name only. Context returns scoped city/team and current action booleans. Preserve CAS and atomic audit, with free text/asset URLs redacted. Acceptance: F05/F11, version-only denial, foreign/revoked assignee, persisted content link, conflicting version, 101+ briefs and all list states. Consumer: main Media component; v2 frontend adaptation remains unassigned.

Acceptance: duplicate link/retry, foreign/unassigned/ambiguous target, failed transaction, no cached secret response, current identity and forced reset.

## C07 — Registration, event fees and check-in

Cancellation/consent enablement remains P01/P02; no old operator flag becomes verified consent. Payload `{status,mutationId,ownerId,expectedRegistrationVersion,attendanceEventId,expectedVersion,expectedResetVersion}` reuses v2 attendance types/statuses and receipt semantics.
