## Native SQLite history check

`python scripts/delivery/c1-sqlite-history.py` executed exact SQL in separate **in-memory SQLite 3.53.1** databases. File attachment/extension loading was denied; no `.env`, database file, account or provider was accessed.

- Main: **9/9 migrations applied**, 55 expected/55 actual tables, no missing modeled columns, zero FK violations in the empty resulting database.
- V2: first **5 migrations applied**, sixth failed with `no such table: batch_settings`. Replay stopped there; the remaining 11 were not attempted. This confirms the missing fresh-install baseline, not corruption of an operational database.
- SQLite migration inventory: main nine, v2 17; two main-only, ten v2-only; seven shared with identical hashes. PostgreSQL: main 17, v2 31; all 17 main files shared with matching hashes, 14 v2-only. Shared hashes do not imply schemas/data are equivalent.

Empty replay establishes table/column existence only, not full constraint/type/default/index parity or upgrade preservation. No PostgreSQL engine replay, populated upgrade, data import or operational history reconciliation ran here. C2 must choose and test forward mappings from fresh and populated main/v2 baselines; existing applied migrations must retain their checksums. Never copy an init into a populated deployment and assume it is safe.
