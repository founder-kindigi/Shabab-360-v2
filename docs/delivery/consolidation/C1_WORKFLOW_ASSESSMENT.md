# C1 workflow decisions

2026-09-11. Source identities are pinned in C1_COVERAGE.json. `main:` refers to published main in the isolated integration worktree; `v2:` refers to the immutable C0 working candidate, including the owner's dirty UI restoration. Line references below and in C1_SOURCE_INDEX.json refer to those copies. These are reconciliation decisions, not an integrated implementation or release approval.

## Assessment method and limits

The path ledger combines source identities, method/capability/persistence/request traces and the workflow decisions below. The commit ledger links actual patch identities and changed paths to those decisions; it does not recommend wholesale cherry-picking. Historical documentation and tests are retained as evidence, not promoted to current operational truth. No path is declared an equivalent replacement on the strength of a name, a component export, or a passing characterization.

Deep inspection and paired execution concentrate on risky changed boundaries: event registration, Media Briefs, attendance calendars/history, conversion, Mashwara, calling template use, audit redaction and workbook parsing. Other dispositions are source-based preservation/adaptation decisions with explicit implementation acceptance requirements. This is not exhaustive line-by-line review of every historical patch, nor a fresh execution of every inherited test. The source index is an index, not behavioral proof. C2/C3 must establish the implemented behavior on the combined candidate.

Common contract requirements for every adapted endpoint: authenticated current identity; effective capability AND canonical hierarchy; deny missing/contradictory assignments; validate bounded IDs, dates, arrays and text before persistence; deliberate 400/401/403/404/409/503 semantics; minimal projections; stable pagination; transactionally required audit/outbox; idempotent mutation/retry where side effects can duplicate. A UI capability signal never authorizes a request. Existing unapproved product lifecycles stay visibly unfinished.

## MP01 — Media Briefs: adapt into v2

Main has persisted collection/detail, assignee/context endpoints and a MediaBrief model; v2 lacks this family. Preserve brief IDs, team/city/content links, creator/assignee/approver, version and status history. `main:src/components/modules/media/media-briefs-page.tsx` requests `/api/admin/media/ui-context`, `/briefs`, `/assignees` and `/briefs/[id]`; `main:src/app/admin/media/page.tsx` redirects to the SPA page ID. The ledger retains exact request/method/capability line references.

Collection reads are bounded; assignees come from active Media-team memberships and active identities. UI-context accepts a team named Media as well as codes, while other paths use codes: reconcile one stable team identity. The UI fixes pageSize at 50 without navigation, and its management controls do not establish that an assigned contributor can perform their own lifecycle. Adapt functionality into the established v2 presentation after an accepted contract. Preserve main tests as intended cases; the four new handler checks expose the version-only authority bypass and discarded content link (F05/F11).

Acceptance: denied override/nonmember/foreign city; active team/assignee and scoped content link; nonempty mutation; version conflict and lifecycle matrix; atomic audit; 51+ briefs with reachable pages; real empty/error/denied states. Main's flawed PATCH must not be restored verbatim.

## MP02 — Events, fees and check-in: adapt into v2

The detailed competing registration contracts remain in C1_PARITY.md. Main's admin registration/eligible-picker/cancel/check-in API family adds behavior absent from v2's root event-registration endpoint. Retain ledger-backed event fees, cancellation history and attendance linkage; retain v2 receipt/version/reset machinery. Resolve capability drift (`events.*` versus `organisation.*`) explicitly. F01–F03/F07–F12 are prerequisites to enabling the merged workflow.

Shared responsibilities, planner items and temporary-team membership routes validate the event's city, but v2 removed group-derived target-city lookup (`src/app/api/admin/events/[id]/responsibilities/route.ts:87`, planner-items:67 and teams/[teamId]/memberships:48). Use canonical hierarchy, not fallback precedence. Main's assignee picker applies a global take(200) before local-city filtering; move scope into the query. V2 removed membership reactivation/conflict handling from the membership POST and the already-revoked guard from responsibility revoke. Preserve history with explicit conditional lifecycle operations, not duplicate rows or successful repeated revocation audits.

The default PWA mounts MobileEventsPage. The actual component displays samples for a real top-level array, empty array and 403, confirmed in an isolated browser at 1280×720 and the denied state at 390×844. No production auth/CSS parity was tested. Main desktop registration controls must become reachable accepted actions in v2 without replacing its mobile design. Acceptance includes real counts/date/venue fields, HQ city selection, cancellation/payment/consent policy, native concurrent capacity and attendance projection under closure/reset/replay. Consent/medical verification and refund policy remain owner decisions; legacy flags must not become proof.

## MP03 — Calendar and off-days: adapt into v2

Main `scheduled-sessions.ts:12–26` limits ordinary attendance to weekend dates and batch-local exceptions. V2 `schedule.ts` adds configured weekdays and extra classes; city operational off-days are a different scope from batch-local exclusions. Both default helpers agree on synthetic Saturday/Sunday/Monday; v2 accepts an explicit extra Monday that main's helper rejects. Preserve both kinds of exceptions and the provenance of calendar decisions. A class-date list must not widen a batch closure to an entire city.

Content session POST on main applies configured batch off-days; v2 removed that step. Reconcile planner, preparation, public/self/guardian schedules and historical reports around one PKT date-only contract. V2 close uses getUTCDay on stored event timestamps (`park/attendance/[eventId]/close/route.ts:39`); this is incompatible with a PKT-midnight timestamp's weekday and needs an actual close-handler boundary test in C2. Do not infer that default-helper tests verify the close route. Acceptance: UTC-host and PKT-host date edges, off-day/extra precedence, batch boundaries, nullable legacy end dates, and stable historical calendar interpretation.

## MP04 — Historical attendance and policy: adapt into v2

Main adds roster snapshots and bounded class/student/murabbi summaries (`src/lib/attendance/summaries.ts:33,111,274,378` and `/api/reports/attendance/*`). A repeated snapshot call includes a newly added participant: the paired synthetic test demonstrates that its snapshot helper is mutable. The main class summary separately exposes snapshot total/unmarked count but computes attendance rate from marked rows (`:468–486`). V2 opportunity calculations and current participant state cannot substitute for immutable historical membership without a migration/transfer ledger.

Preserve source records and snapshot identities; define roster-at-session, marked denominator and scheduled-opportunity denominator separately. Do not relabel one metric as another. Participant transfers and unassigned main participants must remain recoverable. Main's summary missed-week count is not a reliable consecutive streak.

Paired policy checks agree on three contiguous absent weeks but differ for gapped and excused weeks: main resets, v2 pauses/carries earlier evidence. Owner must choose the intended rule; preserve explicit automaticDropoutEnabled=false and do not silently activate a default. Acceptance: transfers, joined/dropout/reactivation dates, missing/excused marks, closed/open events, threshold changes, roster immutability and rollback. Keep v2 conditional state transitions and transactional audit.

## MP05 — Staff attendance: adapt into v2

Main `/api/park/attendance/[eventId]/staff` records staff against a normal group AttendanceEvent; v2 `/api/park/staff-attendance` prepares a park StaffAttendanceEvent and writes a distinct record table. These are different event identities, not renames. Main's GET/POST scope, staff selector, summaries and main tests describe useful behavior, but POST accepts a closed normal session in the new real-handler synthetic test. It has no durable version/reset protocol or transactional audit.

Preserve every old staff record and event association. Define a mapping for date/park/group multiplicity without silent deduplication, and retain v2's dedicated staff capability and operating-day rules. Acceptance: inactive/foreign staff, missing park, duplicate preparation, closed/corrected sessions, history mapping collisions, native unique/CAS races and rollback. No old rows have been migrated.

## MP06 — Search: adapt into v2

Main `/api/search` is a real scoped entity search (`route.ts:105–365`); v2 command palette searches navigation labels only. GET uses people.view, bounded query/limit, requires at least two characters, and returns participant/guardian/staff/batch/group result types. Staff are excluded for a group-scoped actor; guardians are filtered through scoped children. Name/phone/email discovery and subtitles need a projection policy. Main's legacy group.batch.park filters must be replaced by canonical group hierarchy.

Retain useful entity search; do not claim navigation is equivalent. Main queries bounded top-level entities but selects potentially unbounded nested group/participant IDs for counts; use aggregate counts, deterministic ordering and an explicit total/truncation policy. Acceptance: foreign-person nondiscovery, inactive/link-removed identities, restricted field omission, malformed query, all result types, zero results, and a named large synthetic dataset. Source assessment only; full route privacy/query-plan execution remains C2 acceptance, not a claimed C1 equivalence result.

## MP07 — Accounts, profiles and admissions: adapt into v2

Main student/guardian account POSTs link an existing record to a newly generated identity, while invite flows can create new domain records. Preserve link-existing capability, not just an invite button. Main validates active/unlinked targets, guardian children's single city, capability and scope; its transaction updates by ID without a userId:null compare-and-set, so concurrent linking must be redesigned. Normalize email consistently; never store or audit a returned temporary password. Restore explicit private/no-store response headers to password-bearing invite/import responses. Main's admin temporary-password action and program_admin role allowance need explicit privilege mapping to v2's account-management policy.

The main API path `[participantId]/profile` conflicts with v2 `[id]/profile` at the same dynamic route level: consolidate one route, preserving v2 changed-field/versioned saves, nullable clearing, linked guardian/self access and sensitive projections. Retain direct profile pages through the existing target-selection flow; never choose an arbitrary person's identity.

V2 admissions collection/detail/interview handlers contain scoped access, strict input, guarded transitions and transactional audit worth retaining. Main's old inline enrollment PATCH is not safe to revive. The separate conversion route lost main's conditional `accepted AND convertedParticipantId:null` transition: a synthetic competing-winner test returns main 409/rollback versus v2 201/new participant/overwritten winner. Restore CAS, same-city canonical placement and atomic audit in the dedicated conversion contract. Admission status/identity provenance remains intact. Acceptance: duplicate create/link/convert, concurrent conversion, cross-city placement, incomplete interviews, forced reset/revocation, failed audit, no cached secret responses and explicit target identity.

## MP08 — Calling: adapt into v2

Main context/options endpoints provide capability signals and bounded caller/lead pickers missing in v2. Preserve these with v2 active principal, own-assignment interaction checks, active campaign dates, scoped target validation, campaign serialization and transactional reassignment audit. An external caller must not acquire manager/POC authority through the helper used for assignment administration.

V2 lead GET has bounded page inputs and an array output, but loses main pagination metadata/canInteract projection; it includes application phone/name and interaction notes for managers. Resolve management-versus-contact-data visibility explicitly. Campaign detail/update/delete and create routes have distinct authority/lifecycle boundaries; do not infer deletion approval from read access or a visible control. Template-use POST lost caller ownership, campaign/city compatibility, atomic audit and bounded merge-variable allowlisting; a foreign-caller test gives main 403 versus v2 201. Template status also lost its transition graph. Restore these protections while retaining v2's strict bounded assignment input. Calling workbook header aliases Full Name/Mobile Number/Comments were removed; adapt recognized source columns without logging private rows. Acceptance: unrelated/expired/revoked caller denial, scoped pickers, stale campaign/assignment races, template lifecycle/variables, truthful use-versus-delivery, paginated consumers and synthetic source dedupe.

## MP09 — Mashwara: adapt into v2

Main adds action-item PATCH, UI context and task notifications. V2 collection GET omits city filtering when an assigned city is absent; POST trusts request city. Paired tests reproduce foreign-city read/create. Detail access has a separate share/attendee policy; a protected detail helper does not protect collection routes. Restore canonical actor scope before querying or mutating; active shares must not widen the owner's hierarchy rule.

Main decisions validate active same-city teams/assignees and atomically create decision/action/notification/audit; v2 dropped those checks and transaction. Main's action-item PATCH itself checks assignee activity without city/team eligibility, and calls global logAudit from inside a transaction callback. Adapt, do not copy. V2 shares lost main's transactional grant/revoke audit and canonical target lookup. Main notification rows are in-app records marked sent, not provider delivery receipts; the notification module remains defective and external delivery unfinished. Restore bounded metadata channels and idempotent transactional enqueue only after the recipient/read contract. Preserve FK/history behavior in both schemas; native migration source constraints alone do not prove application-level scope. Acceptance: missing/cross scope, revoked shares, assignee/team eligibility, stale mutation, audit/enqueue failure rollback, duplicate notification prevention and escaped minutes/RTL/direct-entry behavior.

## MP10 — Teams: adapt into v2

Both `/api/admin/teams/*` and `/api/admin/collaboration-teams/*` operate on the same memberships but disagree on capabilities, pagination and active-ended membership semantics. Main has dedicated teams.memberships.manage and teams.workspace.* checks; v2 uses organisation.* or membership checks. Preserve capability IDs/override intent and do not translate a denied team grant into broad organisation access. Reconcile the two API families behind one service/contract, retaining compatibility only where a known consumer needs it.

Keep v2 conditional revocation, own-assignment start and transactional activity audit; restore main's active-team/active-staff/contentBlock.teamId validation. V2 activity create/update accepts a content-block ID without validating the block's team. Main nested member PATCH is title-only and rejects ended membership; v2 alternate PATCH can clear endedAt without the same lifecycle. The main workspace helper requires membership even for HQ, a policy conflict requiring an explicit oversight decision. Do not reintroduce main's unversioned writes while recovering its policy. Acceptance: revoked overrides/memberships, ended-but-active rows, wrong team/city, terminal activity states, nonempty bounded updates, duplicate assignment races, cross-team content link and paginated member/activity results.

## MP11 — Content and source imports: adapt into v2

Main permissions endpoint exposes server booleans; v2 removes it and requires cityId in create-plan input. Block/session/detail endpoints mostly retain their logic while reusing the authenticated user for capability checks. Main derives scoped city/park on create; v2 clients and server must agree whether omission is allowed. Preserve stronger v2 city-before-park authorization and version/publish controls; restore missing permission feedback without static role-based authority.

Main parser accepts Week 1 / Day 1 and bounded programme sequences such as Day 24; v2 coerces Number and restricts day to 0–7. Main workbook adapter preserves rich text, formula results and visible hyperlink URL; v2 loses those forms. Synthetic paired tests reproduce label rejection, `[object Object]` content and hidden hyperlink loss. Preserve raw/source provenance and hold unknown/disallowed URLs; displayed text alone cannot establish link safety. Main zero-write preview utilities are useful. Reconcile/seed scripts can write when flags permit: preserve them as historical operator evidence, keep execution gated, and require a future explicit target/staging/import packet. No private workbook rows were copied into this review or imported. Main page wrapper moved into v2's direct component import; preserve behavior rather than duplicate wrappers. Acceptance: source date/category mapping, rich text/formula/link fidelity, zero-write preview, repeatable synthetic import, duplicate detection and planner/park-lesson contract consistency.

## MP12 — Reports and performance: adapt into v2

Main attendance report reads a bounded page plus aggregates; v2 drops pagination and fetches full participant/event joins (`attendance-report/route.ts:110–143`). Main print discloses partial pages (`attendance-report-print.tsx:118–120`); restore that disclosure together with paging, not alone. Main student/dashboard grouped counts became nested record arrays in v2. Keep v2 scope/discount handling and recover aggregate query shape/minimal projections. A reduced query count is not automatically reduced row/memory cost.

Main Prisma warm-instance assignment differs from v2's development-only global assignment; module caching still reuses a loaded module, so do not claim one new client per request without instrumentation. Reconcile measured warm/cold connection behavior and runtime versions. Preserve null-safe chart handling where missing/NaN values would corrupt rendering. Self/guardian schedules and exports need nullable main group preservation, current-versus-historical group semantics and exact totals. HQ first-city/park/person fallbacks are implicit selections, not explicit target review; require a deliberate context before presenting another person's portal. Acceptance: stable multi-page results/exports, 0/empty/null denominators, transfer history, no private over-projection, row/query/memory measurements under a named synthetic workload, and user-visible partial-result disclosure. These performance measurements have not been run in C1.

## MP13 — Foundation, schemas and CI: adapt into v2

Keep v2 durable login throttle, normalized/current identity and revocation, canonical hierarchy, owner-bound receipts, reset generations, exact-money/stock transactions, one-active-batch constraints and deliberate unfinished gates. Main offers missing team/media capability identifiers, broader audit redaction, sensitive response headers, isolated test environment and provider CI checks. Preserve those protections without restoring weaker main identity/offline behavior or widening grants. Unknown old override identifiers must remain recoverable and ineffective until explicitly mapped.

C1_SCHEMA_DIFF.json records both providers' exact changed blocks and migration checksums. Native in-memory SQLite main chain passes 9/9 with 55 modeled tables/columns; v2 fails at its sixth migration because batch_settings does not exist. Main's extra Mashwara SQLite migration rebuilds tables/FKs with CASCADE/SET NULL: inspect orphans and preserve IDs before adopting constraints. No native PostgreSQL or populated upgrade ran in C1. Operational history and production Git trigger remain pre-merge requirements. Main lock versions differ from v2; no claim of current security advisories is made. Restore deterministic tests that cannot inherit a live DATABASE_URL/DIRECT_URL; build and validate both providers in disposable copies after reconciliation.

## MP14 — Repository, documentation, presentation and other evidence: preserve

Keep the current owner-approved v2 mobile design, PWA root, account-bound provider/cache/offline behavior, working uncommitted evidence and professional delivery workflow. Main's AppProviders moved to v2 `components/providers/app-providers`; main logo.svg differs from current PNG branding/service-worker asset rules. Recover safe recovery/debug boundaries within the established design; do not silently expose stack details in production or add a reload loop. RTL/chart/print tests preserve behavioral intent; source-string/export tests are not adequate interaction verification. All main-only/shared tests remain in the recovery history and must be adapted against the final contract, including denied paths; do not retain defective assertions merely to get green totals.

Historical plans, secret-exposure/UAT/performance audits, execution evidence and import contracts remain historical records with their own dates. Current blueprint/owner decisions prevail; C5 rebuilds canonical documentation against the actual main SHA/build. Sensitive datasets, seed/import operators and tracked worktree links must not enter client bundles or a public review artifact. No historical document constitutes current UAT, production secret rotation, import approval or release approval.
