# Data dependencies and staged preservation

2026-09-12. Proposed implementation sequence, not a combined schema or migration result. Read [C1 mapping](C1_DATA_MAPPING.md), its paired schema diff and [contracts](C2_02_CONTRACTS.md). Both source providers contain 55 main / 74 v2 models; all v2 models and applied migration checksums remain required.

| Contract | Data dependency | Decision and remaining evidence |
| --- | --- | --- |
| C01 Media | Main MediaBrief; City, CollaborationTeam, ContentPlanBlock, StaffMeta, User reverse relations | Restore original IDs, version, status, creator/assignee/approver and content link. Preserve metadata without logging it. Schema persistence precedes scoped API/CAS/permission tests. |
| C07 Events | EventFeeSchedule → Event, Batch, FeeEvent; EventRegistration links | Preserve original schedule IDs and event/batch uniqueness. Add nullable main attendanceRecordId, feeScheduleId, cancelledAt and provenance fields where missing; retain createdAt and v2 fields. Conflicting status vocabularies remain source facts, not verified payment/consent. Ledger reconciliation and registration reservation/version/receipt implementation follow separately. |
| C09 historical attendance | AttendanceRosterSnapshot → AttendanceEvent, Participant, Group | Restore original snapshot identities and uniqueness. Schema alone cannot ensure immutable denominators; later API/service tests must prevent repeated capture from adding people. Missing historical roster stays incomplete. |
| C10 staff history | Main staff_attendance_records → AttendanceEvent / StaffMeta; v2 park_staff_attendance_records → StaffAttendanceEvent / StaffMeta | Represent main table with distinct Prisma model LegacyStaffAttendanceRecord mapped to staff_attendance_records. Retain v2 StaffAttendanceRecord and its table unchanged. No event ID reinterpretation or date-only deduplication. Explicit source-session mapping precedes legacy write enablement. |
| C12/C16 calendar | BatchOffDate, BatchOffWeekday → Batch, existing BatchSettings | Restore batch-local exclusions and reasons without converting them into city-wide closures. Do not alter automatic-dropout settings. Shared settings/date-policy adaptation is a later packet with PKT/off-day tests. |
| C04/C09/C17/C19 identities | Participant.groupId and group-delete behavior | Main null placement must remain representable. A later compatibility packet changes nullability/SetNull in both schemas and audits every dependent query, export and DTO. Never invent a group, delete an unassigned person or cascade historical records to make an upgrade pass. |
| C00/C07/C08/C13–16 | OperationReceipt plus endpoint-specific versions and foreign keys | Keep current receipts/token/throttle tables. Define new mutation receipts/versions per service; no schema field alone makes races or stale retries safe. |
| C21 capabilities | Existing role/user overrides, tokenVersion, restricted reconciliation provenance | Preserve both sources on logical collisions; unknown identifiers stay inactive. No automatic grant or last-write-wins import. Collision staging belongs to a separately reviewed data packet. |

The next task is deliberately additive: five main-only models plus the separately named legacy staff model and necessary reverse/nullable linking fields. It does **not** establish a main-to-v2 populated upgrade: required v2 participant placement, unique session keys, shared settings and enum/status/provenance conflicts still need compatibility work. A foundation validation against a synthetic v2 database must not be described as a combined migration rehearsal.

Sequence: C2-03 additive preservation foundation → bounded shared-model/null-placement compatibility and safe native migration baseline → provider-backed combined upgrade/recovery → serial API corrections and exact consumer adapters → independent combined review → separately authorized main merge → documentation rebuilt against the final canonical commit. Only C2-03 is ready now. Each successor needs its own packet after the preceding evidence is accepted.

SQLite's missing fresh-install baseline (F06) remains open. Keep every applied SQL checksum; do not insert or rewrite an old init to simulate safe deployment. Separate schema-created synthetic fixture validation from full migration-history replay. PostgreSQL operational tables/history have not been inspected in C2-02. All future DB execution requires an explicit disposable target, synthetic rows and recovery evidence; this packet authorizes no live access/import.

Private sheet rows remain outside packets, logs and bundles. The [baseline](../baseline/README.md) holds source-reference dispositions; [Gemini's map](../reports/GEMINI_FRONTEND_REFERENCE_MAP.md) controls covered visuals. No new field interpretation, design or desktop/tablet enablement was inferred here.
