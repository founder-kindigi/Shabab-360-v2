# C2-04 — shared-model null-placement compatibility

Assigned to: Astra. Module: consolidation. Status: ready, not active. Depends on C2-03.

## Objective

Prepare a reviewable compatibility candidate for the deliberately deferred `Participant.groupId` nullable placement and its dependent query, delete and authorization semantics. This is not a blanket main-to-v2 merge.

## Required work

Read C2-03 evidence, C1-F04/F06/F17 and the current schemas/migrations before editing. Use an isolated candidate. Define approved behavior for unassigned participants, scoped-role denial when group/park/city context is missing, referential actions, indexes, API queries and legacy rows. Keep SQLite/PostgreSQL aligned where applicable. Do not change an operational database, import data, enable a workflow, change UI, merge or deploy.

Use populated disposable SQLite and native PostgreSQL checks. Prove assigned and unassigned rows, scoped denial, delete behavior, FK/index behavior and rollback/recovery. Run validations, focused tests, relevant regressions, lint, typecheck and provider builds. Record any generated-client limitation precisely. Stop for owner decisions where lifecycle behavior is undefined.
