## Additional source-level concern discovered during comparison

In v2, `src/app/api/events/[id]/registrations/route.ts:158` fetches the supplied participant by ID and active state without validating the participant's hierarchy against the already-authorized event city. The same handler accepts caller-supplied fee/consent/medical values at lines 10–12 and upserts outside a transaction at line 184, followed by an unawaited audit at line 207.

This is fresh static evidence of a boundary/integrity concern in a route outside the completed focused browser checks; it is not a new database/browser reproduction. Include it in MP02's first desired-behavior tests and correct it before merge readiness. Main's alternative registration handler also needs capacity/retry/audit scrutiny; copying that route wholesale does not prove a safe result. No source fixes were made during this planning pass.
