# Deployment Guide

This document outlines the deployment strategy, triggers, and rollback procedures for Shabab 360.

## Vercel Environments

| Environment | Branch | URL | Trigger | Purpose |
|-------------|--------|-----|---------|---------|
| **Production** | `main` | `https://shabab360.vercel.app` | Push to `main` (via PR merge) | Live product |
| **Preview** | `v2` | Generated by Vercel | Push to `v2` | Integration testing |

## Pre-Deployment Checklist

Before merging `v2` into `main` for a production release:

1. **CI validation:** Ensure the GitHub Actions CI workflow passed on `v2`.
   - `npm run typecheck` passes
   - `npm run lint` passes
   - `npm run test` passes
2. **E2E validation:** Ensure core flows work (`npm run test:e2e`).
3. **Database migrations:** Ensure `prisma/postgres/migrations` are up to date and have been reviewed for production data impact.
4. **Environment variables:** Ensure Vercel production environment variables are correct (especially `NEXTAUTH_SECRET`, `DATABASE_URL`).

## Deployment Process

1. Create a Pull Request from `v2` to `main`.
2. Title it `Release: vX.X.X` (following Semantic Versioning).
3. Secure owner approval on the PR.
4. Merge using a standard merge commit (do **not** squash, to preserve history).
5. Vercel will automatically trigger the deployment.
6. Verify deployment by logging into `https://shabab360.vercel.app`.

## Rollback Procedure

If a production deployment introduces a critical regression:

1. Log in to the [Vercel Dashboard](https://vercel.com).
2. Go to the Shabab 360 project.
3. Navigate to **Deployments**.
4. Find the last known stable deployment in the list.
5. Click the three dots (`...`) and select **Promote to Production** (or **Assign Custom Domains**).
6. Once production traffic is restored, identify the issue on `v2` or a `fix/*` branch, fix it, and go through the deployment process again.

## Vercel Configuration Settings

In Vercel Project Settings:
- **Framework Preset:** Next.js
- **Build Command:** `npm run build:postgres`
- **Node.js Version:** 24.x
- **Deployment Protection:** Recommended to enable Vercel Authentication for preview deployments to prevent unauthorized access.
