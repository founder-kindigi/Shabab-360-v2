     8→
     9→## 1. Project Overview
    10→
    11→Shabab360 is a browser-based, multi-role program operations platform for managing Shabab (youth) activities across cities in Pakistan. The organization runs regular sessions at local venues called "parks," organized into batches (time-bound cycles) and groups (participant cohorts).
    12→
    13→### Core Organizational Hierarchy
    14→
    15→```
    16→National HQ (Markazi)
    17→  └── City (City Masoul)
    18→        └── Park (local venue)
    19→              └── Batch (program cycle, e.g., Jan-Jun 2025)
    20→                    └── Group (15-20 participants + 1 Murabbi/mentor)
    21→                          └── Participant (Shabab - the youth)
    22→```
    23→
    24→### Roles
    25→
    26→| Role | Code | Landing Workspace | Primary Job |
    27→|------|------|-------------------|-------------|
    28→| Super Admin | `super_admin` | Admin | Technical recovery, full access |
    29→| Program Admin | `program_admin` | Admin | National oversight, city governance |
    30→| City Head | `city_head` | Admin | City-level ops: parks, batches, people, events, fees |
    31→| Park Admin | `park_admin` | Park | Daily attendance marking, mobile-first |
    32→| Park Lead | `park_lead` | Park | Park attendance with broader privileges |
    33→| Murabbi | `murabbi` | Park | Mentor, tied to one group |
    34→| Guardian | `guardian` | Guardian | Read-only view of linked children |
    35→| Student | `student` | Student | Read-only view of own data |

    58→### 2.2 Critical Architecture Constraint
    59→
    60→**All UI must be served from the `/` route (single `page.tsx`).** The application uses a **Single Page Application (SPA) pattern** with client-side navigation managed by Zustand.
    61→
    62→```tsx
    63→// src/app/page.tsx - The ONLY user-visible route
    64→export default function Home() {
    65→  return (
    66→    <SessionProvider>
    67→      <AppRouter />
    68→    </SessionProvider>
    69→  );
    70→}
    71→
    72→// AppRouter renders different workspaces based on auth state + navigation state
    73→function AppRouter() {
    74→  const { status } = useSession();
    75→  const currentPage = useAppStore(s => s.currentPage);
    76→
    77→  if (status === 'loading') return <LoadingScreen />;
    78→  if (status === 'unauthenticated') return <LoginPage />;
    79→
    80→  return (
    81→    <AppShell>
    82→      <PageRenderer page={currentPage} />
    83→    </AppShell>
    84→  );
    85→}
    86→```

   154→### 2.6 Authorization Pattern
   155→
   156→All authorization is enforced in API routes (server-side), never in the client.
   157→
   158→```typescript
   159→// src/lib/auth/authorize.ts
   160→export function requireRole(allowedRoles: string[]) {
   161→  return async (request: NextRequest) => {
   162→    const session = await getServerSession(authOptions);
   163→    if (!session) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
   164→    const userRole = session.user.role;
   165→    if (!allowedRoles.includes(userRole)) {
   166→      return NextResponse.json({ error: 'Forbidden' }, { status: 403 });
   167→    }
   168→    return null; // Authorized
   169→  };
   170→}
   171→
   172→// Scope helpers
   173→export function requireCityScope(session: Session, cityId: string) { ... }
   174→export function requireParkScope(session: Session, parkId: string) { ... }
   175→```

   749→## 7. Coding Standards
   750→
   751→### 7.1 Naming Conventions
   752→
   753→- **Files:** kebab-case (`attendance-roster.tsx`)
   754→- **Components:** PascalCase (`AttendanceRoster`)
   755→- **Stores:** camelCase with `use` prefix (`useAppStore`)
   756→- **API routes:** kebab-case (`/api/admin/attendance-events`)
   757→- **DB tables:** snake_case (`attendance_records`)
   758→- **DB columns:** snake_case (`participant_id`)
   759→- **Types/Interfaces:** PascalCase (`AttendanceRecord`)
   760→- **Constants:** UPPER_SNAKE_CASE (`ATTENDANCE_STATUS`)
   761→
   762→### 7.2 Component Pattern
   763→
   764→```tsx
   765→// Every page component follows this pattern:
   766→"use client";
   767→
   768→import { useAppStore } from "@/stores/useAppStore";
   769→import { useQuery } from "@tanstack/react-query";
   770→import { PageHeader } from "@/components/layout/page-header";
   771→import { LoadingState } from "@/components/layout/loading-state";
   772→
   773→interface SomePageProps {
   774→  // props from parent
   775→}
   776→
   777→export function SomePage({}: SomePageProps) {
   778→  const { selectedParkId } = useAppStore();
   779→
   780→  const { data, isLoading, error } = useQuery({
   781→    queryKey: ["some-data", selectedParkId],
   782→    queryFn: () => fetch(`/api/park/dashboard?parkId=${selectedParkId}`).then(r => r.json()),
   783→    enabled: !!selectedParkId,
   784→  });
   785→
   786→  if (isLoading) return <LoadingState />;
   787→  if (error) return <ErrorState error={error} />;
   788→
   789→  return (
   790→    <div className="space-y-6">
   791→      <PageHeader title="Page Title" description="Page description" />
   792→      {/* Page content */}
   793→    </div>
   794→  );
   795→}
   796→```
