# UI

- Data-view toggles/tabs (e.g. Today vs Trend, Students vs Murabbis) must render genuinely different, real data — never just change button styling or the heading while the content stays the same. Confidence: 0.72
- Every data view must implement explicit loading, empty (per audience/filter), error, and zero-data states instead of fabricating or silently omitting rows. Confidence: 0.72
- Keep persisted/internal/API enum values stable (e.g. status `excused`) and change only the user-facing label; apply a terminology rename only where the prior label was introduced in the scoped components, leaving unrelated pre-existing wording untouched (and flag it). Confidence: 0.72
- Date-scoped aggregates must be labeled with the real period taken from the response (e.g. `2026-08-19 → 2026-09-17`), so a range aggregate is never presented as "today". Confidence: 0.68
- Graphs/charts must plot only real returned data — no mock points, estimated values, or hardcoded axis labels — and must omit periods with no session rather than zero-filling them; an empty series shows a no-data state instead of an empty/fabricated graph. Confidence: 0.78
- Never fabricate a zero/placeholder as a real data point (e.g. a park with no recorded session); render an explicit "no session/no data" state instead. Headings must be truthful about the underlying data (e.g. "Latest class attendance · 13 Sep 2026"). Confidence: 0.75
- When a single period cannot be stated truthfully for an aggregate view (e.g. several active batches in scope), suppress the single-period label, `Dates:` summary and the chart entirely, show a neutral label (e.g. "All active batches") with an explanatory note, and keep showing the scope-wide real figures — never an arbitrary single-entity name, a false period, or a graph that implies one series. Confidence: 0.70
- Controls for modules/screens that aren't actually implemented for a role must not silently navigate (e.g. loop back to the dashboard); either wire them to a real authorized scoped screen or replace them with a short truthful "not available yet" state, preferring the smallest safe implementation over reusing a legacy page as a disguise for a different role. Confidence: 0.70
- Keep a role's entry into its own workspace/attendance always reachable whenever the server has confirmed real access, independent of whether today happens to have a scheduled session: on a non-class day show the truthful "no class scheduled today" state and still open the workspace with real date navigation, and never let a missing session hide the only action (nor conflate "no class today" with "you have no access to your group"). Confidence: 0.72
- Prefer unambiguous eligible-opportunity wording for attendance/rate figures — e.g. `115 attended out of 360 eligible marks` instead of the ambiguous `115/360 attended`. Keep numerator and denominator as the API's real returned values, present marking completeness as its own distinct figure (`Marked: 1501/1662 (90%)`), and never imply that every entity (park/group) should share the same denominator or rate. Confidence: 0.70
- Consume the server-derived product/role label (e.g. `session.user.roleLabel`) in role screens; never re-derive a "Main admin"/similar label locally from the raw role, and when the server label is absent render no badge/omit the element rather than defaulting to a guessed label. Confidence: 0.65
- In UI-repair/cleanup passes, preserve the established design system from the reference screens (`docs/pwa screens/`): change only state text, conditional rendering, or remove a dead control, and reuse the existing classes/typography/gradients/conventions rather than restyling. Confidence: 0.6
